Code runs server-side as async () => { ...your code... } in node/server.js's own scope. Set output to return a value; console.log(...)/console.error(...) go to [LOGS].

Useful globals:

  • req - the HTTP request (has .body, cookies, etc.)
  • db - the MongoDB database handle (e.g. await db.collection("character").findOne({name:"charname"}) - note: lowercase stored name, not the display name)
  • players[name_to_id["DisplayName"]] - a live, connected character's full server-side state (use the original-casing display name here, not the lowercase stored name)
  • instances[player.in] - the map instance a player is standing in; .monsters is its live monster pool
  • G - all static game data/definitions (G.items, G.monsters, G.maps, G.conditions, ...)
  • settings - this fork's settings.js module (settings.get(), settings.update({...})) - same data as the Admin Panel
  • bots - this fork's bots.js module (bots.connections, bots.is_connected(name))
  • add_item(player, {name:"itemname"}, {q: quantity}), transport_player_to(player, "mapname"), new_monster(instanceName, mapDefObject) - real internal functions, not reimplementations

Everything here runs with full server privileges and no undo - there's no confirmation step. Give/spawn snippets are for a private single-player server; there's no anti-cheat concern here, just be sure of the character name before hitting Execute.
