Code runs as async () => { ...your code... } in main.js's (the web process's) own scope. Set output to return a value; console.log(...)/console.error(...) go to [LOGS].

Useful globals here (main.js's scope):

  • req - the HTTP request (has .body, cookies, etc.)
  • db - the MongoDB database handle (e.g. await db.collection("character").findOne({name:"charname"}) - note: lowercase stored name, not the display name)
  • settings - this fork's settings.js module (settings.get(), settings.update({...})) - same data as the Admin Panel
  • bots - this fork's bots.js module (bots.connections, bots.is_connected(name))

Reaching the game server (a separate process): players, name_to_id, G, instances, add_item(...), transport_player_to(...), new_monster(...) only exist inside node/server.js, not here. To use them, pass a code string through:

  • await bots.local_eval("DisplayName", "...code using player...") - runs the code string over there with player already resolved to that character's live state (original-casing display name, not the lowercase stored name); no-ops if that character isn't connected.
  • await bots.raw_eval("...code...") - same round-trip, no player pre-resolved - use this when you need players[name_to_id["Name"]] yourself (e.g. two characters at once) or nothing character-specific at all (e.g. listing everyone online). Both return whatever that code string sets output to, over there.

Everything here runs with full server privileges and no undo - there's no confirmation step. Give/spawn snippets are for a private single-player server; there's no anti-cheat concern here, just be sure of the character name before hitting Execute.
